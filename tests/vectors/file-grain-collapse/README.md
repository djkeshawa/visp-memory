# File-grain collapse conformance vectors

Version `1.0`. Generated by `visp-intel scripts/emit-collapse-vectors.mjs`;
specified in `docs/consumer-projection.md`, section *File-grain collapse*.

The collapse rule — which projection edges become *file A depends on file B* —
now has more than one implementation: TypeScript in `visp-kit`, Python in
`llm-memory`. Two implementations of one rule drift silently. These vectors are
what stops that: each consumer vendors this directory and runs a conformance
test against it, in its own language and its own CI, so a divergence fails
there instead of surfacing later as a retrieval difference nobody can attribute
to a cause.

## Files

| file | what it is |
| --- | --- |
| `fixture-sources.json` | The whole input. Seven small source files, authored here. |
| `projection.json` | `visp-intel repo projection` of the fixture at head. |
| `projection-superseded.json` | The same snapshot's projection after a second index published a new head. Byte-identical to `projection.json` except `identity.headSnapshotId`. |
| `expected-file-grain.json` | The collapse of `projection.json`: file set, test files, dependency edges, test edges, external dependencies, counts, and every ascribed edge with its honesty fields. |
| `expected-neighbourhoods.json` | Seven seed cases with expected hop maps, including the degradation cases. |
| `manifest.json` | SHA-256 and byte length of each of the above. |

## How to conform

1. Parse `projection.json`.
2. Collapse it by the rule in `docs/consumer-projection.md`.
3. Assert your output equals `expected-file-grain.json`'s `expected` block —
   including the ORDER of every list, which is UTF-16 code unit ascending and
   never locale collation. `src/service/Router.ts` sorts before
   `src/service/api.ts`; under `localeCompare` with no locale argument it does
   not, and that pair is in the fixture for exactly this reason.
4. For each case in `expected-neighbourhoods.json`, run your neighbourhood
   walk with the given seeds and bounds and assert the hop map, the seed
   classification, `truncated` and `reached`.

## What the cases are for

- **two-hop-chain** — the ordinary answer. Catches a walk that follows edges in
  one direction only.
- **spelling-tolerance** — `./src/…` and `src\…`. Catches a raw-string join,
  which reports an empty neighbourhood rather than an error.
- **isolated-file** — a file that is in the snapshot and has no edges.
- **seed-outside-snapshot** — a path the snapshot has never seen. This is a
  DIFFERENT state from the one above and must not collapse into it.
- **unusable-seeds** — absolute, escaping and empty seeds are each rejected with
  a reason, and the usable seed in the same call is still answered.
- **hop-bound-zero**, **file-bound-truncation** — the bounds are honoured, and
  truncation is reported rather than silently returning a short answer.

## Two things these vectors deliberately do not contain

**A verdict.** `expected-neighbourhoods.json` carries integer hop counts. The
`consumerConventionEcho` block restates `decay^hop` for `decay = 0.5` because
two implementations of one consumer-side convention should not be able to
disagree about arithmetic — but the constant is the CONSUMER's, it belongs as a
literal in the consumer's own source where a reviewer sees it in the consumer's
diff, and intel neither chooses it nor endorses it. Likewise
`projection-superseded.json` carries no `stale` flag: it states two snapshot
ids and the consumer decides.

**Any real repository.** The fixture is seven files written for this purpose.
No projection of a benchmark repository, a measured project, or a held-out
task's parent commit may ever be committed here. Freezing one would make
repository structure a prompt input drawn from held-out material, which would
destroy the only honest measurement this project has.

## Regenerating

```
pnpm build && node scripts/emit-collapse-vectors.mjs
```

`--check` regenerates in memory and fails if the committed bytes differ; it runs
as `pnpm vectors:check` inside `pnpm check`. The output is deterministic: the
same bytes under a different temporary directory, a different `LANG`, and a
different checkout path.
